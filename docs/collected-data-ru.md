# Собираемые данные

Полный перечень данных, которые собирает SDK. Названия полей приведены
ровно так, как они уходят на бэкенд.

Данные делятся на два пакета:

- **Снимок** (`POST /api/telemetry/location`) — пассивные данные, читаются
  мгновенно из системы, без обращений к сети.
- **Замер** (`POST /api/telemetry/speedtest`) — активные измерения,
  требуют реального сетевого трафика.

Оба пакета связываются между собой полем `sessionId`.

---

## 1. Подключение к сети — `connectivityInfo`

| Поле | Что означает |
|---|---|
| `connectionType` | Тип подключения: `wifi`, `cellular`, `ethernet`, `none` |
| `carrierName` | Название оператора связи |
| `mcc` | Код страны оператора (Узбекистан — `434`) |
| `mnc` | Код сети оператора внутри страны |
| `cellularGeneration` | Поколение сети: `g2`, `g3`, `g4`, `g5` |
| `dataNetworkType` | Технология передачи данных: `lte`, `nr`, `hspa`, `edge` и др. |
| `isVpnActive` | Активен ли VPN — трафик идёт через туннель, замеры искажаются |
| `isMetered` | Считается ли соединение платным (лимитный трафик) |
| `isAirplaneModeOn` | Включён ли режим полёта |
| `isDataRoaming` | Находится ли абонент в роуминге |

> На iOS доступен только `connectionType`. Остальные поля — `null`:
> система не предоставляет к ним публичного доступа.

---

## 2. Показатели радиосигнала — `cellularInfo`

Ключевая часть для оценки качества покрытия.

| Поле | Ед. изм. | Что означает |
|---|---|---|
| `rsrp` | дБм | Мощность принимаемого сигнала. Основной показатель качества покрытия. Типично от −140 до −44; чем ближе к нулю, тем лучше |
| `rsrq` | дБ | Качество сигнала с учётом помех. Показывает «чистоту» сигнала, а не только его силу |
| `rssnr` | дБ | Отношение сигнал/шум (SINR). Напрямую влияет на достижимую скорость |
| `rssi` | дБм | Общая мощность принимаемого сигнала, включая помехи |
| `cqi` | 0–15 | Индикатор качества канала. Оценка сети: какую скорость она может дать абоненту |
| `asuLevel` | 0–97 | Нормированный уровень сигнала в единицах Android |
| `signalLevel` | 0–4 | Количество «палочек» сигнала — то, что видит абонент |
| `cellId` | — | Идентификатор соты. Позволяет привязать замер к конкретной базовой станции |
| `pci` | 0–1007 | Физический идентификатор соты. Помогает выявлять конфликты сот |
| `tac` | — | Код зоны отслеживания (для LTE/5G) |
| `lac` | — | Код зоны местоположения (для 2G/3G) |
| `timingAdvance` | — | Временна́я задержка сигнала — косвенно указывает на удалённость от вышки |
| `isRegistered` | да/нет | Зарегистрирован ли абонент в этой соте |
| `radioAccessTechnology` | — | Технология доступа. **Только iOS** |

> **Важное ограничение iOS.** Apple не предоставляет публичного API для
> показателей радиосигнала. На iPhone все числовые поля этой группы
> возвращают `null` — доступна только текстовая метка технологии. Это
> ограничение платформы, а не недоработка SDK. Полные радиоданные
> собираются только на Android.

## 3. Местоположение — `locationInfo`

Нужно, чтобы привязать показатели сигнала к карте покрытия.

| Поле | Ед. изм. | Что означает |
|---|---|---|
| `latitude` | градусы | Широта |
| `longitude` | градусы | Долгота |
| `accuracyMeters` | метры | Погрешность определения координат. **Важно для фильтрации:** на Android 12+ абонент может разрешить только приблизительное местоположение — это даёт погрешность 1–3 км, и такие точки непригодны для привязки к конкретной соте |
| `altitudeMeters` | метры | Высота над уровнем моря |
| `speedMps` | м/с | Скорость перемещения. Позволяет отличить замер в движении от стационарного |
| `headingDegrees` | градусы | Направление движения |
| `isMocked` | да/нет | Признак подменённой геолокации. **Такие записи следует исключать:** поддельные координаты искажают карту покрытия сильнее, чем их отсутствие |
| `fixTimestamp` | время | Момент получения координат. Может отличаться от времени замера: по умолчанию берётся последнее известное положение, чтобы не задерживать сбор |
| `status` | — | Доступность геоданных: получены, отказано в доступе, геолокация выключена |

## 4. Состояние устройства — `deviceContext`

| Поле | Что означает |
|---|---|
| `deviceModel` | Модель устройства |
| `osVersion` | Версия операционной системы |
| `batteryLevel` | Уровень заряда, % |
| `isCharging` | Заряжается ли устройство |
| `isAppInForeground` | Активно ли приложение на экране |

Контекст нужен для интерпретации: часть устройств может показывать
худшие результаты из-за режима энергосбережения или старого модема.

---

## 5. Активные измерения — `ActiveMeasurement`

| Поле | Ед. изм. | Что означает |
|---|---|---|
| `downloadMbps` | Мбит/с | Скорость загрузки |
| `uploadMbps` | Мбит/с | Скорость отдачи |
| `latencyMs` | мс | Задержка отклика (пинг). Среднее по 10 измерениям |
| `jitterMs` | мс | Джиттер — разброс задержки. Критичен для звонков и видеосвязи: высокий джиттер даёт прерывания даже при хорошей скорости |
| `dnsResolutionMs` | мс | Время преобразования доменного имени в адрес |
| `tcpConnectionMs` | мс | Время установки TCP-соединения |
| `tlsHandshakeMs` | мс | Время установки защищённого соединения |
| `connectionType` | — | Тип подключения в момент замера |
| `skipReason` | — | Причина, по которой замер не выполнялся (см. ниже) |

### Когда замер не выполняется

Поле `skipReason` объясняет, почему показатели пустые. Это отличает
«не измеряли» от «измерили, и связи не было» — без этого пропуски
занижали бы среднюю статистику по сети.

| Значение | Причина |
|---|---|
| `notCellular` | Устройство было в Wi-Fi. SDK измеряет мобильную сеть, замер по Wi-Fi исказил бы данные |
| `recentlyMeasured` | Замер уже проводился в течение последних 12 часов |

## Расход трафика и периодичность

| Параметр | Значение |
|---|---|
| Периодичность | При запуске приложения, не чаще **1 раза в 12 часов** |
| Максимум замеров | 2 в сутки на устройство |
| Трафик за один замер | до **14,7 МБ** (10 МБ загрузка + 4 МБ отдача) |
| Трафик в сутки | до ~30 МБ в худшем случае |
| Фоновая работа | **Отсутствует.** Только при открытом приложении |

На медленных соединениях расход меньше: измерение ограничено по времени
(4 секунды), поэтому абонент со скоростью 5 Мбит/с потратит около 4,6 МБ,
а не 14,7 МБ.

---

## Надёжность доставки

SDK создан для измерения плохих соединений, поэтому неудачная отправка —
это нормальный сценарий, а не исключение.

- Каждая запись **сохраняется на устройстве до попытки отправки** и
  удаляется только после подтверждения сервером.
- Повторные попытки — с нарастающим интервалом: 30 сек → 1 мин → 2 мин,
  максимум 1 час.
- Записи старше 3 суток отбрасываются: они описывают состояние сети,
  которого уже нет.
- Очередь ограничена 100 записями.

---

## Что SDK не собирает

- Не собирает данные в фоне — только при открытом приложении.
- Не собирает номер телефона, IMEI и другие постоянные идентификаторы
  устройства.
- `sessionId` — случайный идентификатор, создаётся заново при каждом
  запуске приложения и не позволяет отслеживать абонента между сеансами.
- Не собирает содержимое трафика, историю посещений или список
  приложений.
